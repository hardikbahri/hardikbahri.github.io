RAG from reviewer corrections, and the eval that fixed it

Dynamic few-shot retrieval built from emails that reviewers had corrected (Titan embeddings + pgvector). The evaluation suite I wrote found a similarity threshold that was silently blocking 85% of retrievals. I also added an HNSW index that took p50 retrieval from 279 ms to 2 ms at 50K rows.

Choosing the model with real data, not a demo

I benchmarked a TF-IDF + logistic regression classifier against the LLM pipeline. It scored 95% on synthetic emails and 48% on 490 real ones, while the LLM held at 86–89%. That's why the LLM shipped. Then I cut its cost: token tracking, batched inference, and a test showing Claude Haiku + RAG matched Sonnet.

What didn't work, and what I changed

An LLM picking the label for unsure cases

On the hardest complaints it was right 39% of the time against 43% for the classifier, and it called itself high-confidence on 99% of answers.

So the LLM now only writes a note for the reviewer and never sets a label.

XGBoost with Optuna tuning

13 Optuna trials and five engineered text features did not beat TF-IDF + logistic regression, and took 33 minutes of GPU training against 16.

That pointed to a model that reads context, which is where the LoRA fine-tune came from.

Other projects

Earlier builds outside ML: event-driven systems, algorithms and full-stack work.

  • Event-driven flight alerts

    When a flight's status changes in the airport database, MongoDB change streams on a replica set catch the write and publish it to a Kafka topic. A consumer then finds every passenger booked on that flight and date and emails them, and the web app shows the change and a push notification without a reload. The database write alone sets off the whole chain.

    Python, Flask, Kafka, MongoDB change streams and replica sets, React, SMTP Alerts serviceFlight info service

  • Multi-driver delivery route planner

    Plans routes for several drivers at once in four stages: Floyd–Warshall for shortest paths between every pair of stops, K-means to split the stops between drivers, job sequencing to put high-priority orders first, and a greedy TSP to order each driver's route.

    C++, graph algorithms, clustering, scheduling View on GitHub

  • Blockchain messaging between vehicles

    A connected-vehicle network simulation where a roadside unit and 11 cars send messages as Ethereum smart-contract transactions, so a message can't be altered after it's sent. Each car carries a trust score based on its past behaviour, and the app checks how reliable each message is.

    Solidity, Hardhat, MetaMask, React, Express, MongoDB View on GitHub
